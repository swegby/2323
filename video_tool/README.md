# 🎬 Video Stitcher Pro — Batch Colored Preset Edition v4.0 (Aurora UI)

Десктопное приложение для **массовой сборки вертикальных Reels / TikTok / Shorts**
из **5 частей** с цветным мем-текстом, позиционированием рамки мышкой, рандомными
числами (`$2.1k`, `{rand:1.1-2.5}`), персонажами-подпапками и **авто-отправкой
готовых файлов в Telegram** как документ в максимальном качестве.

Работает на **Windows / Linux / macOS** (Python 3.10+).

> **v3.0** — новый движок шрифтов (кириллица больше не «тонкая» и не превращается
> в квадратики) и редизайн GUI по трендам 2026 (Aurora dark theme). См. ниже.

## ✨ Возможности

| | |
|---|---|
| 🎞 **Фильмстрэп всех сегментов** | Лента мини-превью всех 5 сегментов сверху (как в видеоредакторах): живой кадр видео, номер, длительность. Клик — открыть сегмент. |
| ▶ **Настоящий видеопревью** | Выбранный сегмент **проигрывает своё видео прямо в превью** (loop, без звука) с таймкодом, кнопкой паузы и скрабом. Чёрного квадрата больше нет — вместо него кадр видео или красивая заглушка. |
| ⚡ **Быстрый рендер** | Основной рендер — чистый `ffmpeg` (5 сегментов параллельно, склейка `concat -c copy` без перекодирования). MoviePy — только fallback и длительности. |
| 🧩 **Пресеты на каждый текст** | Каждый текст — отдельный пресет со своей позицией, размером, обводкой. До 100+ вариаций на сегмент, при сборке выбирается случайный. |
| 🎨 **Цвета в тексте** | `[blue]TOOWERS[/blue]`, `[red]`, `[yellow]`, `[green]`, `[cyan]`, `[pink]`, `[orange]`, `[purple]`, `[white]`, `[black]` или hex `[#00D5FF]…[/]`. Также `{blue}` / `<blue>`. |
| 🎲 **Рандомные числа** | `{rand:1.1-2.5}`, `{rand:25-100}`, `{rand:1.1-2.5:0.1}`, `{r:…}`, `{random:…}`. Каждая сборка — новый рандом. `1000 → 1k`, `2100 → 2.1k`. |
| 🎯 **Текст точно в рамке** | Исправлен двойной сдвиг оверлея: текст больше не «уезжает» вниз-вправо и не исчезает у нижнего края — печатается ровно там, где рамка в превью. |
| 🔒 **Превью = результат** | Размер шрифта в превью и в финале считается **одной формулой** (убран случайный сдвиг ±3%, превью повторяет CAPS). Чекбокс «🎲 Случайный» на сегменте: снял галочку — собирается именно тот текст, что виден в превью (цвет/размер/позиция точно совпадают). |
| 📐 **Точное позиционирование** | Рамка перетаскивается мышью (8 розовых ручек), стрелки клавиатуры = 1px, Shift+стрелки = 5px, точные спинбоксы X/Y/W/H (0.000–1.000). |
| 👥 **Персонажи** | `folder_1` содержит подпапки-персонажи (`alex/`, `masha/`…). Для каждого — свой Chat ID, куда слать готовое видео. Красивые selectable-кнопки для выбора. |
| ⏱ **Длительности** | Сегмент 0: ускорение `setpts` если длиннее / loop если короче. Сегменты 1–4: обрезка с конца `-ss` если длиннее, целиком если короче. |
| ⚡ **Батч на 1000+ видео** | Последовательно до min / Рандом 2-5. Удаление или перемещение в `output/used`. Многопоточность 1–8. Авто-отправка в Telegram после каждого файла. |
| 🔍 **Умный ffmpeg** | saved → PATH → общие пути → bundled (imageio-ffmpeg) → авто-скачивание. Путь запоминается в `ffmpeg_path.json`. |
| 💾 **Автосейв** | Всё пишется в `project.json`: сегменты, пресеты, экспорт, батч, UI (дебаунс 700 мс + таймер 5 с). |
| 🖼 **Красивый GUI** | Тёмная тема `#0a0a14`, карточки с градиентами и тенями, FlowLayout чипов, кастомные скроллбары/слайдеры/чекбоксы. |

## 🚀 Установка и запуск

```bash
cd video_tool
python -m venv venv
# Windows: venv\Scripts\activate   |   Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
python main.py
```

При первом запуске приложение само:
1. скачает **ffmpeg** (bundled через imageio-ffmpeg, ~25 МБ) или найдёт системный;
2. скачает **шрифты** Anton (латиница) и Oswald-Bold (кириллица) с Google Fonts.

## 🧑💻 Быстрый старт

1. **Кинь видео**: по 1+ видео в `folder_2`…`folder_5`; в `folder_1` создай подпапки
   персонажей (`alex/`, `masha/`…) и положи туда их видео.
2. **Настрой сегменты** (справа): для каждого из 5 — видео, длительность, тексты.
   Текст пиши с цветами и рандомом: `2. Go to [blue]TOOWERS[/blue] {rand:1.1-2.5}`.
   Рамку двигай мышкой в превью; размер/обводка — слайдерами.
   ➕ Добавляй вариации текста (чипы сверху), при сборке выбирается случайная.
3. **Персонажи** (слева): вставь Bot Token, ✅ проверь, выбери персонажей кнопками,
   укажи Chat ID (`-100…`) каждому, включи 📤 Авто-отправку.
4. **Экспорт**: разрешение 1080×1920 / 720×1280 / Оригинал, FPS 30/24/60,
   качество CRF16–CRF23, звук, CAPS, эконом-режим.
5. **▶ Build** — одно видео. **⚡ BuildBatch** — весь батч (настрой: режим,
   удаление/перемещение, количество, потоки).

|---|---|
| `[blue]TOOWERS[/blue]` | цветное слово |
| `[#00D5FF]неон[/]` | свой hex-цвет |
| `{blue}текст{/blue}` или `<blue>текст</blue>` | тоже работает |
| `{rand:1.1-2.5}` | 1.1 … 2.5 шаг 0.1 |
| `{rand:25-100}` | целое 25–100 |
| `{rand:1.1-2.5:0.1}` | явный шаг |
| `$2.1k` | значения ≥1000 → `1k`, `2.1k` |
| Enter | перенос строки (сохраняется) |
| Ctrl+Enter | добавить новый текст (пресет) |

## 💬 Telegram

- Бот создаётся через **@BotFather** → токен вида `123456:ABC-DEF…`.
- Chat ID группы: добавь бота в группу, напиши туда что-нибудь, открой
  `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — `chat.id` вида `-100…`.
- Готовые файлы отправляются как **документ** (`sendDocument`) — без сжатия.
- Отправка идёт автоматически после каждой сборки (одиночной и батча), если
  включена 📤 Авто-отправка.
- Если Telegram отвечает «group chat was upgraded to a supergroup» — приложение
  **само исправит Chat ID** на новый (`-100…`) и сохранит его. Кнопка «📤 Тест»
  отправляет тестовое видео и тоже чинит ID.

## ⚙️ Параметры экспорта

| Качество | CRF | preset | Когда |
|---|---|---|---|
| 💎 Макс CRF14 slow | 14 | slow | почти без потерь (для MOV), лучшее качество |
| ⭐ Высокое CRF18 | 18 | medium | рекомендуется |
| ⚖️ Баланс CRF20 | 20 | fast | средний размер/скорость |
| 🚀 Скорость CRF23 | 23 | veryfast | быстро, меньше размер |

**Качество для MOV (важно):**
- 💎 **10-бит цвет** — если исходник 10-бит (iPhone HEVC / ProRes в `.mov`),
  вывод сохраняет 10 бит (`yuv420p10le`, профиль High10) — нет бандинга на градиентах.
- 🌫 **Размытый фон вместо обрезки** — для горизонтальных/квадратных видео экран
  заполняется размытой копией, а оригинал встаёт по центру без потери контента
  (по умолчанию жёсткий кроп 9:16).
- В режиме «💎 Макс» звук кодируется 256 kbps вместо 192 kbps.

## 🛠 Технические детали

- ffmpeg-цепочка сегмента:
  `scale=W:H:force_original_aspect_ratio=increase:flags=lanczos, crop=W:H:exact=1,
  fps=N, setpts (ускорение), overlay=0:0 (PNG уже позиционирован), format=yuv420p`
  + `-preset -crf -pix_fmt yuv420p -movflags +faststart`.
- **Важно про текст**: текст на каждом сегменте рисуется в полноразмерный RGBA-PNG
  уже в абсолютных координатах рамки и кладётся на видео оверлеем в (0,0) — поэтому
  текст виден ровно там, где ты поставил рамку (в т.ч. внизу экрана).
- Если шрифты `fonts/` не скачались/не скопированы — приложение использует
  системный шрифт с кириллицей (Arial/DejaVu), текст всё равно печатается.
- Склейка: `concat demuxer -c copy` (мгновенно), fallback — ре-энкод `concat` фильтр.
- Сегменты рендерятся параллельно (адаптивно к RAM: `min(5, RAM/700MB)`),
  с ретраем упавших сегментов.
- Превью: первый кадр/скраб через MoviePy в фоновом потоке, ресайз до 300×534
  (экономия RAM ×10), дебаунс 180 мс, флаг одного потока загрузки.

## 🔧 Шрифты и текст — исправлено в v3.0

Раньше текст «ломался» на глазах. Найдены и устранены реальные баги (проверено
инструментально через fontTools):

| Было (баг) | Стало (v3.0) |
|---|---|
| **Anton не содержит кириллицы вообще (0 глифов)** → любой русский текст и плейсхолдер «Текст» превращались в квадратики-«тофу» | Шрифт выбирается **по всей строке**: если в тексте есть хоть одна кириллическая буква — вся строка идёт шрифтом **Oswald** (в нём есть и Latin, и Cyrillic). Anton остаётся только для чисто латинских мемов. |
| **`Oswald-Bold.ttf` — это variable-шрифт с весом 400 (Regular!)** Загрузчик сохранял variable-файл под именем «Bold», но вес никто не выставлял → кириллица рисовалась **тонким Regular**, а латиница тяжёлым Anton — рассинхрон по толщине | Оси `wght` теперь принудительно ставится тяжёлый инстанс (Bold, 700) **и в рендере (Pillow), и в превью (Qt)** → кириллица такая же плотная, как латиница. |
| **Рендер выбирал шрифт по каждому слову**, а превью — по всей строке → в смешанном тексте (рус+англ) слова «прыгали» по высоте, а превью ≠ финальное видео | Решение теперь **строковое и в рендере, и в превью** — все слова в одной строке на одном шрифте, с одинаковыми метриками. Превью = результат. |
| Шрифты подключались в фоне уже после показа окна → первое время превью рисовалось тонким системным шрифтом-заглушкой | Шрифты регистрируются в Qt **синхронно до показа окна**, а после фоновой загрузки превью принудительно перерисовываются. |
| Дубликат класса `_ThumbLoader` (копипаста), кнопка «глаз» токена ломалась (Показать→Скрыть→👁) | Удалено. Кнопка корректно переключает «Показать»/«Скрыть». |

## 🎨 Дизайн-система (v4.0 — Aurora, тренды 2026)

Полная переработка GUI по актуальным гайдам тёмных интерфейсов 2026
(«evolved dark mode», Material dark, Linear/Vercel-стиль):

- **Палитра**: фон `#0B0C11` (глубокий сине-угольный, **не чистый чёрный** —
  это главный принцип тёмного режима 2026), поверхности-«elevation»
  `#14161E → #1A1D27 → #232734` (иерархия глубины), текст
  `#EDEFF5 / #A2A8BB / #6C7283`.
- **Один спокойный акцент** — индиго-фиолетовый градиент `#6E8BFF → #9B73FF`
  (кнопки, чипы, выделения, слайдеры, прогресс); батч — тёплый янтарь
  `#F0A93C → #F6BE63`. Никакого «вибрирующего» неона.
- **Глубина через границы и мягкие свечения**, а не грубые тени; скругления
  8–18px, сетка отступов 4px, более тяжёлые начертания для читаемости на тёмном.
- **Фокус-кольца** акцентного цвета на полях ввода, аккуратные сегментированные
  вкладки сайдбара, тонкие скроллбары, чистые текстовые подписи на кнопках.

## 🌗 Темы и горячие клавиши (v4.0)

- **Тёмная (Aurora) и светлая (Aurora Light)** темы. Весь интерфейс построен на
  единой системе дизайн-токенов: QSS генерируется из активной палитры, а
  кастомные отрисовки (превью, миниатюры, бейджи) читают те же токены — поэтому
  смена темы перекрашивает всё приложение целиком и мгновенно.
- Переключатель — кнопка 🌙/☀ в шапке. Выбор сохраняется в `project.json`
  (`ui.theme`) и подхватывается при старте.
- **Горячие клавиши**: `Ctrl+B` — собрать видео, `Ctrl+Shift+B` — батч,
  `Ctrl+S` — сохранить проект, `Ctrl+T` — сменить тему, `1`–`5` — перейти к
  сегменту. Стрелки в превью двигают рамку (1px), `Shift+стрелки` — на 5px.
- У приложения есть **иконка окна** (рисуется в рантайме, без файла-ассета).

## 🖥 Адаптивная вёрстка (v2.9)

- **Боковая панель — 4 вкладки**: «Экспорт», «Персонажи», «Батч», «FFMPEG».
  Каждая секция — отдельное меню со своим скроллом, ничего не обрезается.
  Минимальная ширина каждой карточки ровно подогнана под ширину панели.
- **Создание персонажа работает**: новая пустая подпапка сразу видна в списке

- Окно можно растягивать как угодно — **от узкого до вертикального монитора**:

- **Шапка** — 2 строки: кнопки Build/BuildBatch наверху, статус + прогрессбар

- **Фильмстрэп** — миниатюры сегментов автоматически масштабируются под ширину
  окна (не вылезают за край и не сжимаются в точку).
- **Превью видео** — размер адаптируется к карточке (220–340 px ширины),
  всегда по центру, ничего не обрезается.
- **Чипы текстов** — высота подстраивается под реальное количество строк
  (до 5 строк), дальше — прокрутка. Старые чипы удаляются из дерева сразу,
  без «призраков», наезжающих на новые.
- **Сайдбар** — ширину можно менять перетаскиванием (320–470 px).

## ❓ Частые проблемы

- **Ошибка при старте `ValueError: invalid literal for int()`** → старый/повреждённый
  `project.json` (например, в `batch.mode` вместо числа записана строка). Удали
  `project.json` — приложение создаст новый; современные версии сами чинят
  повреждённые значения при загрузке.
- **«ffmpeg не найден»** → открой карточку «⚙️ FFMPEG» → «⬇️ Скачать» (или выбери вручную).
- **Батч ничего не собрал** → в `folder_2…5` должны быть видео; в `folder_1` —
  подпапки персонажей с видео.
- **Текст не виден в превью** → включи «Скраб» и «Эконом (без превью)» выключен.
- **Рандом меняется** → да, `{rand:…}` пересоздаётся при каждой сборке пресета.
